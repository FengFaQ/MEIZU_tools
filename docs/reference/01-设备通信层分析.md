# 01 · 设备通信层分析（魅族「煤油工具箱」BFF）

> 分析对象：`bin\` 下 9 个负责"与设备说话"的批处理模块
> 代码来源：`_ref_meiyou\_utf8\`（GBK→UTF-8 转码副本），文件名规则 `bin\x.bat` → `bin__x.bat.txt`
> 引用格式：`文件名:L行号`，全部结论均来自实际读到的代码；无法确认处标注 **未确认**

---

## 0. 阅读前须知：这一层的通用写法

设备通信层不是"库 + 调用者"，而是 9 个**多入口批处理脚本**（multi-entry batch），每个文件用第一参数当 `goto` 标签：

```bat
@ECHO OFF
set args1=%1& set args2=%2& ... & set args9=%9
goto %args1%
```

- 入口分发：`bin__write.bat.txt:L18-L19`、`bin__read.bat.txt:L11-L12`、`bin__info.bat.txt:L10-L11`、`bin__partable.bat.txt:L12-L13`、`bin__clean.bat.txt:L13-L14`、`bin__slot.bat.txt:L7-L8`、`bin__mzbox.bat.txt:L11-L12`、`bin__framework.bat.txt:L15-L16`
- 参数约定：最多 9 个位置参数，`args1` = 子命令，其余按各子命令注释里的签名解释
- **返回值靠全局变量名约定**，不是 `exit /b` 码。模式：
  ```bat
  SETLOCAL            :: 子命令内开局部作用域
  ...业务...
  ENDLOCAL & set <模块>__<子命令>__<字段>=%值%
  ```
  例：`bin__chkdev.bat.txt:L184`（`chkdev__mode` / `chkdev__port` / `chkdev__port__<mode>`）、`bin__info.bat.txt:L116`（`info__qcedl__*`）、`bin__write.bat.txt:L266`（`write__adbpush__*`）、`bin__read.bat.txt` 无回传、`bin__partable.bat.txt` 无回传、`bin__slot.bat.txt:L56,L98,L146`（`slot__*`）、`bin__mzbox.bat.txt:L80,L142,L162,L304`（`mzbox__*`、`edlsetbootablestoragedrive__value`）
- 统一错误出口 `:FATAL`：每个文件末尾都有几乎相同的实现（`bin__chkdev.bat.txt:L194-L195`、`bin__write.bat.txt:L573-L574` 等），打印"脚本遇到问题"并 `pause` 后 `EXIT`
- 统一日志：`call log %logger% <I|W|E|F> <文本>`，实现见 `bin__log.bat.txt:L11-L13`（`gettime.exe` 打时间戳 + 级别 + 模块名 + 文本，追加 `%logfile%`）
- 统一彩色输出：`ECHOC {%c_xx%}文本{%c_i%}{\n}`，颜色变量由 `bin__framework.bat.txt:L98-L106` 的 `:THEME` 注入

**状态机只有一个事实源**：`chkdev` 探测出的 `chkdev__mode` / `chkdev__port`，其余模块全部读它或直接把 `mode` 当参数传进来。设备模式取值域：`system` / `recovery` / `sideload` / `fastboot` / `fastbootd` / `qcedl` / `qcdiag` / `sprdboot` / `mtkbrom` / `mtkpreloader`。

## 2. 模块详述

### 2.1 `chkdev.bat` — 设备检测（连接状态机的唯一入口）

**子命令接口**（`bin__chkdev.bat.txt:L3-L13`）

```
call chkdev <mode> [rechk] [复查前等待秒数, 默认3]
  mode ∈ system recovery sideload fastboot fastbootd
         qcedl qcdiag sprdboot mtkbrom mtkpreloader all
```

**两条实现路径**

| 路径 | 用于 | 探测手段 | 判定"多设备" | 判定"无设备" |
|------|------|---------|-------------|-------------|
| `:chkport`（`L51-L74`） | qcedl/qcdiag/sprdboot/mtkbrom/mtkpreloader | `devcon.exe listclass Ports` | `find "[2]"` 命中 | `find "[1]"` 未命中 |
| `:chkadb`（`L77-L94`） | system/recovery/sideload | `adb.exe devices -l` | 行号 ≠ 1 | 行号为空 |
| `:chkfastboot`（`L97-L118`） | fastboot/fastbootd | `fastboot.exe devices -l` + `getvar is-userspace` | 行号 ≠ 1 | 行号为空 |
| `:chkall`（`L121-L180`） | `auto` 场景（9 个调用方在用） | 端口→fastboot→adb 三级串联，累计 `devnum` | 任一环节 >1 即报错 | `devnum==0` 继续轮询 |

**端口名 → COM 号提取技巧**（本层最巧的一处）

```bat
busybox.exe sed -i "s/ /\r\n/g" %tmpdir%\output.txt        :: L68  一行拆成多行
for /f "tokens=1 delims=(COM) " %%a in (
    'type %tmpdir%\output.txt ^| find "(COM"') do set port=%%a   :: L70
```
`delims=(COM)` 把 `(`、`C`、`O`、`M`、`)`、空格全部当分隔符，于是 `(COM12)` 的第 1 个 token 直接就是 `12`——不需要正则、不需要 `substring` 定位。

**fastboot 与 fastbootd 的区分**（`L111-L115`）

```bat
fastboot.exe getvar is-userspace 2>&1 | find "is-userspace: yes" && set var=y
if "%mode%"=="fastboot"  (if "%var%"=="y" 重试)   :: 期望 n
if "%mode%"=="fastbootd" (if "%var%"=="n" 重试)   :: 期望 y
```
即：**同一个 `fastboot devices` 列表，用 `is-userspace` 这一个变量区分两种模式**，判错就当作"没到位"继续轮询。

**关键设计点**
- 轮询上限 `trytimes_max=30`（`L24`），超出后 `pause` 让用户按键重试（**不退出**），见 `L84/L103/L129`
- adb 分支每轮 `TIMEOUT /T 1`（`L90,L109`）；**端口分支没有任何等待**，且 `trytimes` 上限判断被注释掉（`L57`），注释里也明说"端口检测不等待且无限循环"（`L23`）→ 纯忙等
- adb 前置：`adb.exe start-server` 失败即提示"请退出其他占用 adb 的软件"并重试（`L79`）
- `:chkall` 的多设备判定很严格：端口设备数、fastboot 数、adb 数**任一路径 >1 直接报错**，最后再要求三大类总数为 1（`L176-L177`）
- 多设备时会把 `output.txt` 内容 `type` 出来并追加进日志（`L66,L91,L110`），便于排错

**失败处理**：参数错误 → `FATAL`（`L39`）；处理后文本失败 → `FATAL`（`L68`）；读端口号失败 → 端口路径静默重试（`L71`）、`chkall` 路径 `FATAL`（`L149`）；未连接 → `pause` 后从头重试。

### 2.2 `reboot.bat` — 跨模式重启编排

**子命令接口**（`bin__reboot.bat.txt:L3-L7`）——用"支持矩阵"直接写在注释里：

```
call reboot <frommode> <tomode> [chk|rechk] [如果rechk则填秒数]
  system    → system recovery fastboot fastbootd qcedl qcdiag sprdboot poweroff
  recovery  → system recovery fastboot fastbootd qcedl sideload sprdboot poweroff
  fastboot  → system recovery fastboot fastbootd qcedl poweroff
  fastbootd → system fastboot fastbootd
  qcedl     → system recovery fastbootd qcedl
```

**"支持矩阵"是真的可执行表**，不是文档摆设：

```bat
find /I ":%frommode%-%tomode%" "%framework_workspace%\reboot.bat" || goto UNSUPPORT   :: L18
...
goto %frommode%-%tomode%                                                              :: L28
```
即：**标签存在即支持**。文件里实际存在的 `from-to` 标签共 **29 条**，与注释矩阵逐条对应：`SYSTEM-` 8 条、`RECOVERY-` 8 条、`FASTBOOT-` 6 条、`FASTBOOTD-` 3 条、`QCEDL-` 4 条。其中两条路径还有"机型变体"子标签，由 `%edlplan%` 等变量二次分派：`FASTBOOT-QCEDL-{CMD,KEY,EDLCABLE}`（`L109` 按 `%edlplan%` 跳转）与 `FASTBOOT-RECOVERY-{CMD,MISC}`（`L92` 固定走 CMD）。不支持的组合（如 `fastbootd→qcedl`）走 `:UNSUPPORT`（`L217-L219`）：提示"请手动进入目标模式，完成后按任意键继续"，**当作成功继续**。

**动作表**

| from → to | 实际命令 | 行 |
|---|---|---|
| adb 系 → system/recovery/fastboot/fastbootd/qcedl | `adb.exe reboot` / `reboot recovery` / `reboot bootloader` / `reboot fastboot` / `reboot edl` | L169-L187 |
| adb 系 → sprdboot | `adb.exe reboot reboot autodloader`（**注意 `reboot` 重复**） | L190 |
| adb 系 → poweroff | `adb.exe reboot -p` | L194 |
| adb 系 → qcdiag | `su` 取 root → `whoami` 校验 == root → `setprop sys.usb.config diag,adb` | L46-L54 |
| recovery → sideload | `adb.exe shell twrp sideload` | L78 |
| fastboot → recovery | `fastboot.exe oem reboot-recovery`（备选方案 `-MISC`：刷 `misc_torecovery.img` 再 `reboot`） | L94 / L96-L99 |
| fastboot → qcedl | 按机型配置 `%edlplan%` 三选一：`oem edl` / 手动按键 / 9008 线+`fastboot reboot` | L107-L121 |
| fastboot → poweroff | `fastboot.exe oem poweroff` | L124 |
| qcedl → system | `fh_loader --sendxml=<power value="reset">`，依次尝试 ufs/emmc/spinor | L136-L142 |
| qcedl → qcedl | `fh_loader --sendxml=<power value="reset_to_edl">` | L156-L162 |
| qcedl → recovery / fastbootd | 刷 `misc_torecovery.img` / `misc_tofastbootd.img` 后 `reset` | L144-L154 |

**关键技巧**
- **qcedl 出发的"重启"本质是复位**：只有 `reset` / `reset_to_edl` 两种 XML，`--skip_configure` 表示不动已建立的 Firehose 会话（`L139-L141`）。三种存储类型**盲试**（ufs→emmc→spinor），任一条返回 0 即成功——因为复位命令不依赖正确 memoryname 也能被解析。
- **机型级危险拦截**：`meizu20inf` 进 fastbootd 会"设备报废"，脚本两次 `input choice` 确认后才继续（`L20-L25`）；`conf\dev.csv` 里该机型标注"不支持9008"（`bin__conf__dev.csv.txt:L19`）。
- **收尾自动复查**：`:FINISH` 里按 `chk/rechk` 参数回调 `call chkdev <tomode>`（`L222-L225`），`poweroff` 跳过。

**失败处理**：`:FAILED`（`L211-L216`）打印失败 + 两个选项「再次尝试 / 我已进入,可以继续」——**把"脚本判断错了"这种正常情况做成一等公民**，这是本层最人性化的设计。

### 2.3 `write.bat` — 写操作（本层最大模块，575 行）

**子命令接口**（`bin__write.bat.txt:L3-L14`，完整照抄）

           fastboot      分区名               img路径

#### 2.3.1 `qcedlsendfh` —— Sahara→Firehose 握手 + configure（核心中的核心）

流程（`L23-L134`）：

1. 校验引导文件存在并展开成绝对路径（`L34-L36`）
2. `port=auto` → `call chkdev qcedl`，取 `chkdev__port__qcedl`（`L38-L39`）
3. **注意**：`L30` 有一行 `set configuremode=%storagetype%`，**无条件覆盖了 args4**。即第 4 参数 `auto/emmc/ufs/spinor/skip` 实际上被机型配置 `%storagetype%`（来自 `conf\dev-<product>.bat`）顶掉，`auto` 盲试分支（`L91-L98`）基本是死代码。**这是一个真实缺陷，见 §6**
4. Sahara 发送：`QSaharaServer.exe -p \\.\COM%port% -s 13:%filepath%`（`L58`，走 `:QCEDLSENDFH-MEIZU`，`L51` 写死 `goto QCEDLSENDFH-MEIZU`，`-COMMON` 分支保留但不可达）
   - 成功判据**两个**：输出含 `File transferred successfully`（`L59`），或含 `[portstatus]firehose`（`L60`，说明设备已在 Firehose 态、无需再灌）
   - 失败 → 提示"请将设备重新进入9008"后**回到步骤 2 重来**（`L83-L84`）
5. **EDL 授权探测**：`fh_loader.exe --port=... --nop --skip_configure --noprompt`（`L65`），在输出里找 `Authenticate failed`（`L69`）；找不到 → "未发现授权需求，跳过发 sig"
6. **授权码下发**：读 `res\%product%\bak\edlauthcode.txt` 第一字段（`L75`），用 `%edlauthcode:~511,1%` 与 `~512,1%` **校验长度必须正好 512 字符**（`L76-L77`）；然后
   ```
   qcedlcmdhelper.exe -p COM%port% -m sig -d %edlauthcode%      :: L79
   ```
   成功判据 `Authenticate success`（`L81`）；失败 → 提示重试并从**第 4 步重发引导**（`L82`）
7. **configure（建立可读写会话）**：`:qcedlsendfh-configure-run`（`L105-L134`）
   - 生成 XML（`L109-L112`）：`<configure MemoryName="..." Verbose="0" AlwaysValidate="0" MaxDigestTableSizeInBytes="8192" MaxPayloadSizeToTargetInBytes="1048576" ZlpAwareHost="1" SkipStorageInit="0" />`

#### 2.3.7 两个"点名要求"的澄清：`persist` 保护 与 `_a/_b` 槽位后缀

这两件事**都不在设备通信层内实现**，必须说清楚归属，否则容易误判本层职责：

**(a) `persist` 保护 —— 本层为零**
`write qcedl <分区名>` 对分区名**不做任何白名单/黑名单**：给什么名字就往 GPT 里找什么名字，找到就写（`L451-L462`）。`clean qcedl` 同理，任何分区都能被 `<erase>` 掉（`L53`）。全项目唯一的 `persist` 保护发生在**主入口、且只针对"回读备份包"这一条路径**：
```bat
::煤油工具箱.bat.txt:L405-L406
::不刷入persist分区以免损坏tee
busybox.exe sed -i "s/ filename=\"persist.img\" / filename=\"\" /g" %sel__folder_path%\...\images\rawprogram0.xml
```
即：备份完成后，把 `rawprogram0.xml` 里 `persist.img` 的 `filename` 清空（`filename=""` 的 program 节点在 `fh_loader` 语义里=只写 GPT 记录、不写数据，与 `mzbox:L249` 的跳过写法一致）。**所以：用本层 API 直接 `call write qcedl persist xxx.img` 是可以把 persist 刷坏的**，保护完全依赖调用方自律。

**(b) `_a` / `_b` 槽位后缀 —— 也是调用方拼的**
本层 9 个模块内**没有任何一处拼接 `_a`/`_b`**。`slot.bat` 只负责"读写当前槽位值"（回传 `slot__cur` / `slot__cur_oth`），后缀拼接全部在主入口完成：
```bat
::煤油工具箱.bat.txt:L498   call read qcedl recovery_%slot__cur% ...
::煤油工具箱.bat.txt:L505   call read qcedl boot_%slot__cur% ...
::煤油工具箱.bat.txt:L1118  set targetpar=%bootpar%_%slot__cur%   （ab 时）
::煤油工具箱.bat.txt:L1073  call write fastboot %bootpar%_%slot__cur% ...
```
设计分工是：`slot` 提供"槽位事实"，调用方负责"用事实拼分区名"。好处是通信层不必知道机型的分区命名规则；代价是**拼错没人管**——`write qcedl boot_a` 若设备实际只有 `boot`，会在 `L451` 的 lun 循环里一路走到 `lun==lunnum` 才 `FATAL 找不到分区`，报错信息与真实原因（槽位后缀错了）距离较远。

**readgpt**（`L236-L321`）

**writegpt**（`L136-L233`）

- **四种回写后端**（`L202-L233`）：
  | 模式 | 实现 |
  |---|---|
  | system | `write adbpush` → `su` + `dd if=... of=/dev/block/... bs=%filesize% count=1` |
  | recovery | 同上（无 su） |
  | fastboot | `fastboot.exe flash partition:%lun% <格式化后文件>`（`L226`） |
  | qcedl | 生成 `<program ... label="PrimaryGPT" start_sector="0" num_partition_sectors="%filesize_sec_*">` 再 `fh_loader --sendxml --search_path`（`L229-L232`） |

**各操作的 gpttool 调用**（这是本层"用外部工具做数据结构编辑"的集中体现）
```
mkpar    : gpttool -p tmp.bin -f mkpar:auto:%parname%:%parstart_sec%:%parend_sec%:%partype%:%parflag%   :: L112
rmpar    : gpttool -p tmp.bin -f rmpar:%basisinfo%                                                     :: L80
editpar  : gpttool -p tmp.bin -f editpar:%basisinfo%:%attriinfo%                                       :: L57
mvpar    : gpttool -p tmp.bin -f mvpar:%basisinfo%:%direction%:%length_sec%                            :: L34
switchslot: gpttool -p x.bin -f switchslot:%target% -o y.bin                                          :: slot.bat:L159
```
`mkpar` 的 `start` / `end:xxx` / `size:xxx` **都接受字节值**，由 `call calc b2sec ...` 换算成扇区（`L100-L107`）；`size:` 用加/减 1 求闭区间末端。

### 2.7 `slot.bat` — A/B 槽位

**子命令接口**（`bin__slot.bat.txt:L3-L4`）

```
call slot [system recovery fastboot fastbootd qcedl auto] set [a b cur cur_oth]
          [system recovery fastboot fastbootd qcedl auto] chk
```

**三条通路，三种数据源**

| devmode | 读当前槽位 | 写槽位 | 行 |
|---|---|---|---|
| system / recovery | `adb shell getprop ro.boot.slot_suffix` → 用 `delims=_` 去掉下划线 | `framework adbpre bootctl` 推送后 `bootctl set-active-boot-slot 0/1`（system 带 `su`） | L38, L63-L67 |
| fastboot / fastbootd | `fastboot getvar current-slot` + `fastboot getvar all` 取 `slot-unbootable:_a/_b` | `fastboot set_active <a\|b>` | L76-L92, L106 |
| qcedl | 逐 lun `readgpt` → `gpttool print:default:#inf:sector:10` → 抓 `[BasicInfo]Slot_Current` | `gpttool switchslot:` 改本地 GPT → 逐 lun `writegpt` → `setbootablestoragedrive` | L125-L183 |

**qcedl 路径的槽位状态机**（`L131-L142`）—— 处理了 5 种 GPT 反馈：
```
Slot_Current a            → slot_cur=a, oth=b
Slot_Current b            → slot_cur=b, oth=a
Slot_Current undefined    → 视为 aonly（slot_cur=a）
Slot_Current nonexistent  （仅 chk）→ slot_cur=aonly
Slot_Current unknown      → 失败重试
同时出现 a 和 b            → 失败重试（矛盾状态）
```
关键实现细节：**先按 lun 收集所有 `Slot_Current` 行到 `output2.txt` 再统一判定**（`L128`），而不是边读边覆盖——避免多 lun 互相覆盖。

**A/B 槽位写入的完整链路**（`L151-L185`）：
1. 对每个 lun 跑 `gpttool -f switchslot:<target> -o gpt_main<n>_new.bin`（`L159`）
2. 成功判据 `[Info]All Done.`（`L161`）；**若报 `[Error]Slot switching is not supported. No _a or _b partitions detected.` 则直接复制原文件当"无需改动"**（`L162-L165`），不视为失败
3. 逐个 lun `writegpt`（`L172`）
4. **最后必须写 `setbootablestoragedrive`**（`L174-L183`）：
   ```
   emmc/spinor → value=0
   ufs + 目标 a → value=1
   ufs + 目标 b → value=2
   <setbootablestoragedrive value="N" />  → fh_loader --sendxml
   ```
   这一步是 UFS 特有的：**UFS 有多个 LUN（物理分区），固件需要知道从哪个 LUN 引导**，只改 GPT 不够。

**机型级危险拦截**：`meizu20inf` 切槽位"会导致设备报废"，双重 `input choice` 确认（`L17-L21`）。

**fastboot 路径的不可启动警告**（`L103-L104`）：目标槽位 `slot-unbootable=yes` 时先警告再让用户确认——这是 A/B 机型最常见的翻车点（刷了半截、槽位却没切/切到了坏槽）。

### 2.8 `clean.bat` — 格式化 / 擦除

**子命令接口**（`bin__clean.bat.txt:L3-L9`）

  | formatexfat | `mkfs.exfat` | `[-n 卷标]` | L111-L112 |
  | formatfat32 | `mkfs.fat` | `-F 32 [-n 卷标]` | L138-L139 |

  `L140`/`L168` 留了 `-S %disksecsize%` / `-s %disksecsize%` 的注释（对齐扇区大小，当前未启用）。

#### 2.9.1 身份三件套：psn / socid / chipid

| 通道 | psn 来源 | socid 来源 | chipid |
|---|---|---|---|
| adb（`L24-L81`） | `ro.vendor.meizu.hardware.psn` → `ro.boot.psn` → `ro.meizu.hardware.psn`（后者优先，`L32-L37`） | `ro.soc_id` / `ro.vendor.soc_id`（`L42-L43`），按长度分 4 种机型规格裁剪（`L44-L68`） | **`psn` + `socid` 右补 `0` 到 48 位**（`L71-L76`） |
| fastboot（`L146-L163`） | —（sn 取 `fastboot devices -l` 第 1 列） | `getvar socid` | `getvar chipid`，校验第 48 位（`L153-L154`） |
| 9008（`L84-L143`） | `fh_loader --nop` 输出的 `INFO: PSN:`（`L98`） | `INFO: Chip serial num:`，**先用 `busybox sed a→A…z→Z` 全部转大写**（`L103-L104`） | 优先 `CHIPID:` 行（`L108`），失败则 `psn+socid` 拼接补零（`L117-L121`） |

**psn 长度校验写法很巧**：`if "%psn:~15,1%"==""` 且 `if not "%psn:~16,1%"==""` → 恰好 16 字符（`L38-L39`）。同样手法用于 socid 的 11/12/16/39 位分支（`L44-L47`）。

**BL 锁状态**：`find "Lock state: locked"` → `no`；`find "Lock state: unlock"` → `yes`（`L138-L139`）。注意 `write.bat:L67-L68` 里同样的探测被注释掉了，改成了更保守的 `Authenticate failed` 判据（`write.bat:L69`）。

**兜底降级**：socid 读不到时，"从 chipid 里去掉 psn 前缀取前 8 位"，并明确 `log W` 标注"此结果可能不准确"（`L127-L133`）——**降级但留痕**，值得学。

#### 2.9.2 `edlreadall` —— 全分区回读 + 生成可再刷的 9008 包

这是本层最复杂的流程（`L166-L272`），产物结构：
```
<保存目录>\
  images\                      :: 各分区 .img
  for_ROM_maker\
    orig\   partition.xml  rawprogram0..N.xml  gpt_main<N>.bin  gpt_backup<N>.bin
    generate\                  :: ptool.exe 生成的标准刷机 xml
    本目录说明.txt / readme.txt
  flash_all.bat                :: 顺带生成 fastboot 线刷脚本
```
步骤：
1. 端口 auto → `chkdev qcedl`；可选发引导（`L178-L183`）
2. `info qcedl` + 校验 `portstatus==firehose`（`L185-L186`，**该检查因 §2.5.1 恒真**）
3. 写 `partition.xml` 头：`WRITE_PROTECT_BOUNDARY_IN_KB=0`、`SECTOR_SIZE_IN_BYTES=<secsize>`、`GROW_LAST_PARTITION_TO_FILL_DISK=true`（`L196-L202`）
4. 逐 lun：
   - `partable readgpt ... gptmain` 与 `gptbackup` **两份都读**（`L209-L210`）
   - `gpttool print:default:default:sector:10` 取分区行（`L214`）
   - `gpttool -f print:qcedl_partitionxml` 直接把分区表**转成 partition.xml 片段**（`L218`）——省掉手写结构转换
   - 生成"待回读分区清单" `edlreadall-parlist.txt`，**默认 `[userdata]` `[last_parti]` `[mindowsesp]` `[mindowswin]` `[mindowsdat]` 已去掉方括号（= 不回读）**，用 `sed` 实现（`L222-L224`）
   - `edlreadall_customize=y` 时才开 Notepad3 让用户改（`L168`、`L225`）——**默认静默，需要时才交互**
   - 逐分区：在清单里能 `find "[%parname%]"` 的才回读并写 `filename="<parname>.img"`，否则写 `filename=""` 并 `log I 跳过`（`L246-L256`）
   - lun 收尾时**自动补两条 GPT 记录**（`L233-L243`），并按 ufs/非 ufs 分开：
     ```
     ufs     : PrimaryGPT 0,6 扇区          BackupGPT NUM_DISK_SECTORS-5., 5 扇区
     非 ufs  : PrimaryGPT 0,34 扇区         BackupGPT NUM_DISK_SECTORS-33., 33 扇区
     ```
     对应 4096B/512B 扇区下的 GPT 实际大小（6×4096=24KB vs 34×512=17KB，与 §2.5.1 的探测常量完全一致）
5. 全部 lun 完成后 `ptool.exe -x partition.xml -t generate`（`L261-L265`，**先判存在**）
6. 一次性 `call read qcedlxml %port% %memtype% %imgpath%\images %xmls%`（`L267`）——所有 lun 的 rawprogram 拼成一个逗号列表**一次批量回读**
7. `copy rawprogram*.xml` 到 images（`L269`）

#### 2.9.3 `edlsetbootablestoragedrive`（`L275-L305`）
和 `slot.bat:L174-L183` 是同一件事的两个副本：`auto` 时先 `info qcedl` 定型；ufs 走 `call slot qcedl chk` 取 `slot__cur`（`aonly`/`a`→1、`b`→2；emmc/spinor→0），再发 XML。代码里注释 `::注意: 此处需要修改slot.bat`（`L295`）——作者自己标注了这段耦合是临时方案。

#### 2.9.4 `confdevpre`（`L308-L323`）与 `adbchkfinddev`（`L15-L21`）
- `confdevpre`：读 `conf\dev.csv` 的表头行 `[product],[model],...` 作为变量名序列（`L314`），按 `%product%` 取同一列的值（`L316`），逐个 `call framework conf dev-%product%.bat <名> <值>` 写配置（`L317`），最后 `call conf\dev-%product%.bat` 立刻生效（`L322`）。**用 CSV 单表驱动全部机型差异**，是本项目最值得抄的设计。
- `adbchkfinddev`：检查 `com.meizu.flyme.service.find` / `com.meizu.flyme.find` 是否存在（`L17-L18`），缺失则**警告"可能隐藏了账户锁，刷机后可能被锁"**并要求确认（`L20`）。属于安全/合规兜底。

## 5. 设计优点

1. **"标签即能力表"的重启矩阵**（`reboot:L18`）
   `find ":%from-%to%" reboot.bat` 决定是否支持，不支持的组合自动降级为"请手动进入，然后继续"。文档注释（`L3-L7`）和实现天然同步，加一个组合只需加一个标签。29 条路径零散乱。

2. **端口名解析的 `delims=(COM)` 技巧**（`chkdev:L70`）
   一行解决 `(COM12)` → `12`，比 `set port=%var:~5,-1%` 更健壮（位数不定）。

3. **9008 会话的三层自适应重试**（`write:L120-L130`）
   把 Firehose `configure` 阶段的三种典型不兼容（Hash table 上限、ZTE OEM 校验、payload 上限）**自动改写 XML 重试**，并且用设备自己回报的 `MaxPayloadSizeToTargetInBytesSupported` 做参数协商——这是真正理解协议的做法，不是碰运气重试。

4. **一切以 `port_trace.txt` 为判据，而不是退出码**
   `fh_loader` 的退出码不可靠，作者把 `Got the ACK for the <configure>`、`Couldn't find the file`、`Failed to parse sparse file`、`Filesize is 0 bytes.`、`Erasing the whole disk`、`Authenticate failed/success` 全部转成可判定条件。**同一套 trace 既做成功判据，又做失败分类，还做安全阀**。

5. **"异常刷机包"归为警告而非致命**（`write:L382-L412`）
   缺文件 / 坏 sparse / 0 字节镜像只会 `log W` 并列出文件名继续刷——避免用户因为包里一个无关分区空文件而整包重来。

6. **读写同构**（`write qcedl` ↔ `read qcedl`，`qcedlxml` ↔ `--convertprogram2read`）
   同一份 GPT 解析代码、同一套 XML 结构、同一个 `fh_loader`，只翻一个开关。代码量减半，坑只需踩一次。

7. **三个后端压成同一个函数名后缀**（`info:L289` `:paranddisk-read512kb-%chkdev__mode%`、`partable:L305` `:readgpt-read512kb-%mode%`、`L214` `:writegpt-write-%mode%`）
   `goto 标签-%变量%` 的"表驱动分派"，让"同一语义、三种设备模式"的实现保持平行，读代码时一眼看到对应关系。

8. **危险操作的分级确认**
   - 机型级硬拦截：`meizu20inf` 进 fastbootd / 切槽位 → 双重选择（`reboot:L20-L25`、`slot:L17-L21`）
   - 全盘擦除检测：`Erasing the whole disk` → `FATAL`（`clean:L55`）
   - 覆盖已存在文件：`read`/`partable` 均 `pause` 确认（`read:L26,L56,L84,L174`、`partable:L244`）
   - 缺口锁风险提示：`mzbox:L20`
   全部是"默认安全，显式放行"。

9. **CSV 单表驱动机型差异**（`mzbox:L308-L323` + `conf\dev.csv`）
   `conf\dev.csv` 首行是中文显示名，第二行 `[product],[model],[cpu],[storagetype],[blplan],[parlayout],[bootpar],[edlplan],[done]` 才是**变量名序列**（`bin__conf__dev.csv.txt:L1-L2`），下面 28 行机型数据（`L3-L30`）。`confdevpre` 用 `tokens=<列号>` 逐列取值并 `call framework conf dev-<product>.bat <名> <值>` 落地（`mzbox:L314-L317`），最后 `call conf\dev-<product>.bat` 立即生效（`L322`）。通信层只消费 `%storagetype%` / `%parlayout%` / `%bootpar%` / `%edlplan%` 这些抽象变量，**正文不含任何 `if "%product%"=="16S"` 式机型硬编码**——唯一的机型特判是 `meizu20inf` 的危险拦截，共 2 处（`reboot:L21`、`slot:L17`）。

10. **adb push 的三重保险**（`write:L203-L262`）
    空间预判（含已存在文件大小扣除）→ `bff.tmp` 中转避免覆盖 → 传后大小严格比对。

11. **失败只降级不崩**：`reboot:FAILED` 给"我已进入,可以继续"；`configure` 失败 `log W` 继续；`slot` 的 `switchslot` 不支持时 `cp` 原文件当成功。

## 6. 缺陷与风险

> 分级：**P0** = 会导致功能失效或数据风险；**P1** = 特定条件下出错；**P2** = 代码卫生/可维护性

### P0-1 `info qcedl` 的 `portstatus` 被写死，导致全层"端口就绪保护"集体失效
`bin__info.bat.txt:L44` 无条件 `set portstatus=firehose`，`L45` 直接 `goto QCEDL-FIREHOSEMODE`；原始探针（`QSaharaServer -p ... -d` 读 `[portstatus]`）在 `L37-L43` 被整段注释。
**后果**：所有依赖 `info__qcedl__portstatus` 的检查永远不成立——
`write.bat:L445`、`clean.bat:L38`、`mzbox.bat:L186`、`slot.bat:L116` 四处"端口不在 firehose 模式 → 报错重试"的保护全部**假通过**；`read.bat:L143` 的同类检查早已被注释掉，等于整条 `read qcedl → read qcedlxml` 链路（`read.bat:L110`）也没有保护。
真实表现：设备还停在 Sahara 态（没发过引导）时，脚本不会提示"请先发送引导"，而是直接把 `fh_loader --sendxml` 怼上去，得到一堆 `port_trace.txt` 报错后再让用户重试——**排查方向被完全带偏**。

### P0-2 `slot.bat` 的 `set` 功能被一行 `&` 短路（三个模式全中）
```bat
:CHK-ADB
if not "%func%"=="set" ENDLOCAL & set slot__cur=%slot_cur%& ... & goto :eof    :: L56
goto SET-ADB                                                                   :: L57  ← 永不执行
```
`if cond cmd1 & cmd2 & cmd3` 的语义是**只有 cmd1 受条件控制，后面全部无条件执行**，因此 `goto :eof` 恒执行，`:SET-ADB` 不可达。同样问题在 `L98-L99`（`:CHK-FASTBOOT` → `:SET-FASTBOOT`）与 `L146-L147`（`:CHK-QCEDL` → `:SET-QCEDL`）。
**后果**：`call slot <mode> set <target>` 只读不写，**切换槽位功能整体失效**（调用方 `煤油工具箱.bat.txt:L437`）。判定依据是 cmd 的 `if`/`&` 结合语义，此结论在源码层面可直接复现。

### P0-3 `chkdev` 端口分支是无限忙等，且重试上限被注释
`bin__chkdev.bat.txt:L57` 整行注释；`L59-L65` 循环体内**没有任何 `TIMEOUT`**（对照 `L90`/`L109` 的 adb/fastboot 分支有 1 秒延迟）；注释 `L23` 自认"端口检测不等待且无限循环"。
**后果**：`chkdev qcedl` 在设备不在线时把 CPU 打满，且永不返回、永不给"未连接"提示（adb/fastboot 分支 30 次后会 `pause` 提醒，端口分支不会）。主入口对 `qcedl` 的调用多达约 20 次，最坏情况是用户面对一个刷屏的空转窗口。

### P1-1 `partable` 的端口探测被 `&` 短路，`qcedl + port=auto` 组合拿到的是过期端口
```bat
if "%mode_arg%"=="auto" call chkdev all 1>nul & goto READGPT-2         :: L246  goto 恒执行
if "%mode%"=="qcedl" (if "%port_arg%"=="auto" call chkdev qcedl ...)   :: L247  ← 永不可达
...
if not "%mode_arg%"=="auto" set mode=%mode_arg%                        :: L250  mode 到这里才确定
if "%mode_arg%"=="auto" set mode=%chkdev__mode%
```
`writegpt` 完全同构：`L152` 短路掉 `L153`，`%mode%` 到 `L156` 才赋值。

**后果**：`mode_arg=qcedl`（非 auto）且 `port_arg=auto` 时，
1. `L247` 的 `if "%mode%"=="qcedl"` 判断的是**尚未赋值的 `%mode%`**（`SETLOCAL` 不清变量，取到的是上一次调用残留值），条件不成立 → `chkdev qcedl` 永不执行；
2. 但 `L160-L162` 仍会 `set port=%chkdev__port__qcedl%` —— 拿到的是**上一次探测的过期端口号**（可能对应一台早已拔掉的设备）。
3. 于是 `fh_loader --port=\\.\COM<过期号>` 失败，且失败信息指向"端口不存在"，而不是"没探测到设备"。

触发面很宽：`partable:L31,L37,L54,L60,L77,L83,L109,L115`（mvpar/editpar/rmpar/mkpar 全部四个编辑类子命令）都以 `auto` 作为端口参数调用 `readgpt`/`writegpt`，**这条组合正好命中**。同一模式在 `readgpt` 的 `L246-L247` 与 `writegpt` 的 `L152-L153` 各有一份。

### P1-2 `write qcedlsendfh` 的 `configuremode` 参数被机型配置无条件覆盖
```bat
set configuremode=%args4%          :: L27
set configuremode=%storagetype%    :: L30  ← 无条件覆盖
```
**后果**：第 4 参数 `auto/emmc/ufs/spinor/skip` 完全无效，`L91-L100` 的 `auto` 盲试与 `skip` 分支是死代码。当 `conf\dev.csv` 的 `storagetype` 与实际设备不符（例如刷入他人备份包/改装机），configure 只会尝试一种存储类型，失败后仅 `log W` 继续（`L133`），后续读写很可能出问题。

### P1-3 `configure` 重试计数用错变量：`set n=0` 却 `set /a num+=1`
```bat
:qcedlsendfh-configure-run
set targetstoragetype=%1
set result=n
set n=0                  :: L108  ← 初始化了 n，但后续从不使用 n
...
:qcedlsendfh-configure-run-1
set /a num+=1            :: L114  ← 递增的是 num
...
if "%num%"=="5" (call log %logger% E 配置端口-...-失败.重试次数过多 & goto ...-failed)   :: L119
```
**后果**：`num` 在 `:qcedlsendfh-configure-run` 内**从未被初始化**。该标签位于 `qcedlsendfh` 子命令自身的 `SETLOCAL`（`L24`）作用域内，但 `SETLOCAL` 只隔离"写入"、不隔离"读取"——`num` 会继承外层/上次调用的残留值。而 `write` 模块内 `num` 被大量复用为循环计数器（如 `qcedlxml:L325-L346` 的 XML 计数、`qcedl:L449` 的 lun 计数）。若残留 ≥5，**第一次 configure 尝试就会被判"重试次数过多"直接失败**；且因为失败只 `log W` 继续（`L133`），现场表现是"configure 一遍过却报失败，随后刷写各种异常"。触发概率随会话变长而上升，属于典型"偶发、难复现"故障源。

### P1-4 `writegpt` 用 `%chkdev__mode%` 判定 fastboot
```bat
if not "%chkdev__mode%"=="fastboot" (set var=gptmain) else (set var=gptboth)   :: L164
```
此处应判断已解析出的 `%mode%`。`chkdev__mode` 只有在本子命令内实际调用过 `chkdev` 才被刷新（`L152` 被短路时根本不会调用），因此**显式指定 `fastboot` 且未走 auto 分支时 `var` 会错成 `gptmain`**，`fastboot flash partition:<lun>` 拿到的镜像缺备份 GPT。

### P1-5 `reboot` 的 sprdboot 命令拼写错误
`adb.exe reboot reboot autodloader`（`L190`）多了一个 `reboot`。按 adb 语义这会把 `reboot` 当目标传下去，大概率失败；由于 `:FAILED` 会提示用户手动处理（`L211-L216`），故障被掩盖成"自动重启失败"。

### P1-6 `write qcedlxml` / `read qcedlxml` 的 XML 列表带前导分隔符
`write:L345` 用 `set xml_new=%xml_new%,%path%`（首个元素前即有逗号）；`read:L127` 则先把 `/` 全部换成 `,`，同样产生前导逗号。**未确认** `fh_loader --sendxml` 是否容忍空元素（工作日志不可得）；若不容忍，则单 XML 场景也会异常。属"依赖外部工具宽容量"的隐性假设。

### P1-7 A/B 与 `misc` 相关操作缺少"槽位未切换"的收尾
`reboot qcedl recovery` / `qcedl fastbootd`（`L144-L154`）通过刷 `misc_torecovery.img`/`misc_tofastbootd.img` 实现，但**没有校验目标槽位是否可启动、也没有在事后清理 misc**。若目标槽位损坏或 misc 未被系统消费，设备可能重复进入 recovery。对比 `slot.bat:L103-L104` 有 `slot-unbootable` 警告，此处没有对应保护。

### P2-1 `info` 中大量死代码
`L70-L113`（存储类型实测 + UFS LUN 探测，约 44 行）、`L46-L60`（Sahara msmid→SoC 查表）、`L32-L33`（oemid）全部不可达。`bin__slot.bat.txt:L40-L49`（`/proc/cmdline` 判槽位）、`L139-L141` 也是注释残留。这些代码本身质量不低，挂着不用会误导后续维护者（**极易被误认为"当前生效逻辑"**）。

### P2-2 一个概念多份实现
`setbootablestoragedrive` 在 `slot.bat:L174-L183` 和 `mzbox.bat:L289-L302` 各写一遍（后者注释 `L295` 自认"此处需要修改 slot.bat"）；GPT 512KB 读取在 `info.bat:L277-L305`、`partable.bat:L293-L321` 各写一遍；`GPT 定位分区` 在 `write:L450-L461`、`read:L98-L109`、`clean:L43-L53` 三处同构复制。任何一处修 bug 都要改 2-3 处。

### P2-3 错误处理风格不统一
- 致命：`goto FATAL`（退出脚本）
- 可重试：`pause` + `goto <本段开头>`（用户必须敲键，无法脚本化/无人值守）
- 静默降级：`log W` 后继续（`configure` 失败、`switchslot` 不支持）
三者混用且**没有统一退出码**，主入口无法判断"到底成没成"——只能靠回传变量是否为空。这使无人值守/批量刷机不可能实现。

### P2-4 日志中可能夹带敏感数据
`write.bat:L152` 与 `read.bat:L63` 都明确注释"原始输出包含设备 IMEI"，但**只提示"自行注释掉 type 行"，默认仍写入日志**。`mzbox` 会把 PSN/SocID/ChipID 全量 `log I`（`L79,L141,L161`）。日志目录按 `framework_lognum=6` 滚动保留（`framework:L152`），历史设备身份信息会留存 6 份。

### P2-5 依赖"命令输出文本"的解析非常脆
大量 `for /f "tokens=N delims=..."` 直接钉死外部工具的输出列位与措辞：`gpttool` 的 `tokens=4,5`（`write:L456`）、`tokens=2..9`（`info:L218`）、`QSaharaServer` 的 `[portstatus]`/`[msmid]`（`chkdev` 注释、`info:L48`）、`fh_loader` 的 `tokens=7 delims=' `（`mzbox:L98`）、`tokens=6`（`L108`）。任一工具升级/换语言就会静默错位。代码对这种风险的唯一缓解是"取回值再交叉校验"（如 `info:L219` 校验分区名、`mzbox:L110-L111` 校验 chipid 长度），但没有版本锁定或版本检测。

### P2-6 `%tmpdir%` 共用导致并发不安全
所有中间文件都是固定名：`cmd.txt`、`cmd.xml`、`tmp.xml`、`tmp.bin`、`output.txt`、`output2.txt`、`port_trace.txt`。`framework:L138-L139` 提供 `framework_multitmpdir=y` 来隔离（`tmp\<时间戳>`），但**默认 `n`**（`L138`）。同机跑两个实例必然互相踩。
